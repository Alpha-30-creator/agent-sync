# 0001 — Project name: agent-sync

**Status:** accepted (2026-08-25)

**Context.** The working name was "skillsync". `skillsync` is already taken on npm (v1.3.8) by
[jinzheio/skillsync](https://github.com/jinzheio/skillsync) — "Sync Agent Skills to Cursor, Claude,
Codex and more": a much narrower tool (skills only; no MCP, no plugins, no routing rules, no
per-project scoping, no cross-device sync). Our agent-native install depends on `npx <name> setup`,
so a name collision is unusually dangerous: an agent following our INSTALL.md would fetch a
different tool.

**Decision.** Name the project `agent-sync` (npm package, GitHub repo, CLI binary, skill prefix).
Free on npm and GitHub as of 2026-08-25. The name also signals the broader artifact scope (skills +
MCP + plugins, and rules/memory later) rather than skills alone.

**Consequences.** Skill pack ids are `agent-sync-create-skill`, `agent-sync-add-mcp`, `agent-sync`.
Store lives at `~/.agent-sync/`, manifest is `agent-sync.yaml`, project marker is `.agent-sync.yaml`.
Keep the hyphen consistently: `agentsync` (no hyphen) is a *different* published package in an
adjacent space.

**Alternatives rejected.** Scoped `@handle/skillsync` (weaker discovery, longer install line);
package `skill-sync` with binary `skillsync` (leaves `npx skillsync` fetching someone else's tool —
unacceptable for an agent-driven installer).
